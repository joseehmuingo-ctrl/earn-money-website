# Earn Money — sign-up, login, dashboards, M-Pesa starter

This project is a deployable **starter** for a membership website. It includes:
- Email/password registration and login
- Password hashing with bcrypt
- Session cookies and basic rate limiting
- A member dashboard that is locked until payment confirmation
- An admin dashboard with member and payment summaries
- Safaricom Daraja STK Push integration scaffold
- Server-side callback handling with amount/receipt checks

## Before you deploy

**The project is not live-payment-ready until you supply your own Daraja production credentials, business shortcode, public HTTPS URL, and callback configuration.** The sample does not use or collect the customer's M-Pesa PIN.

A personal phone number such as `0718068366` is not a Daraja shortcode. For automatic STK Push, configure a supported business Till/Paybill and the matching transaction type. Make sure the business account is yours or you have permission to collect these payments.

## Run locally on a computer

Requires Node.js 20 or newer.

1. Extract the ZIP.
2. Copy `.env.example` to `.env`.
3. Set `SESSION_SECRET` and a strong `ADMIN_PASSWORD`.
4. Run `npm install`.
5. Run `npm start`.
6. Open `http://localhost:3000`.

The site can be tested locally for registration/login. Live Daraja callbacks require a public HTTPS endpoint; localhost cannot receive Safaricom callbacks directly.

## Daraja setup

1. Create/sign in to your Safaricom Daraja developer account: https://developer.safaricom.co.ke/
2. Create an app and test using sandbox credentials first.
3. For live collection, complete Safaricom's Go Live/business onboarding for your shortcode and API product.
4. Configure `.env` with `MPESA_ENV`, `MPESA_CONSUMER_KEY`, `MPESA_CONSUMER_SECRET`, `MPESA_SHORTCODE`, `MPESA_PASSKEY`, and `MPESA_CALLBACK_TOKEN`.
5. Deploy to a service that supports Node.js, a persistent disk, environment variables, and HTTPS. Set `BASE_URL` to that public HTTPS origin.
6. Use the callback path generated by the app: `/api/payment/callback?token=YOUR_CALLBACK_TOKEN`. Register/allow the callback as required by your Daraja setup.
7. Test a successful payment, cancellation, timeout, duplicate callback, wrong amount, and delayed callback before accepting real payments.

Daraja reference: https://developer.safaricom.co.ke/

## Admin account

At first start, if `ADMIN_EMAIL` does not exist, the server creates it using `ADMIN_PASSWORD`. Change the example password before deploying. Do not share the admin login. Existing accounts are not automatically reset when you change the environment variable.

## Hosting and database warning

This starter uses SQLite. Deploy only on a host with a **persistent disk** and ensure `DB_PATH` points to that disk. If your host has ephemeral storage or multiple app instances, use a managed production database instead. The default Express memory session store is for development/small demos only; use a persistent session store such as Redis or a database-backed store for production.

## Security work recommended before a public launch

- Add CSRF protection and an appropriate production session store.
- Add email verification and password-reset flows.
- Add audit logging, backups, monitoring, and an admin 2FA option.
- Confirm callback authenticity and reconcile transactions using Daraja's transaction-status/query facilities where appropriate; callback token alone is not a full cryptographic signature.
- Use HTTPS only; keep secrets in the hosting provider's environment settings, never in frontend code or GitHub.
- Add privacy policy, terms, refund rules, contact details, and a clear explanation of what members receive for the KSh 150 fee.
- Do not advertise guaranteed earnings unless you can substantiate them. Explain the actual service and how members may benefit.
